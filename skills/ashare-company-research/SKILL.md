# A股公司深度调研

本技能判断一家A股公司是否可能被市场重新定价，而不是证明“公司很好”。核心框架：

```text
预期差 × 催化剂 × 盈利兑现 × 估值位置 × 资金偏好 × 风险释放节奏
```

默认中文输出，写成研究证据、情景和证伪条件，不给个性化投资指令。

标准/深度报告或用户明确要求“可视化/HTML/研报页面”时，同时交付结构化研究与自包含 HTML。视觉系统必须与 `ashare-daily-market-review`、`ashare-capital-environment-dashboard` 一致：深墨绿网格背景、宋体研报正文、金色眉题、米白纸张卡、细棕边、5px 硬投影、等宽数字与来源元数据。首页式营销落地页、无来源的评分环和伪造K线不属于本技能输出。

## 一、研究边界

确认或合理推断：

- 公司名称、股票代码和交易所。
- 截止日期与研究周期；默认今天、未来1周到6个月。
- 输出模式：快速诊断、标准报告、深度报告、同行比较或观察计划。
- 用户已知假设和最关心的问题。

公司不明确且无法可靠推断时停止并询问。用户要从一个股票池找公司时，先使用 `ashare-stock-screening`，不要把筛选逻辑塞进本技能。

## 二、证据与点时纪律

优先级：交易所/监管披露 → 公司定期与临时公告、投资者关系记录 → 政府/行业协会 → 可信金融数据平台 → 可核验媒体与研究资料。

每个关键数字至少标明数值、单位、观察期、发布日期、访问时间和来源。严格区分：

- `事实`：公开披露或可直接观察。
- `推断`：由事实支持的机制解释。
- `判断`：对市场影响与概率的观点。

报告期末不等于发布日期。回看历史日期时，只使用当时已经发布的资料。来源冲突时并列数值和口径，说明采信理由；不要平均冲突数据。

数据严重不足时降级为快速诊断，只输出已确认事实、缺口及其影响。不得用0、行业均值、区间估算或模型默认值填补缺失事实。

## 三、三阶段流程

### 阶段A：建立初始判断

按以下十一个问题形成报告：

1. 公司真正靠什么赚钱，市场给哪块业务估值？
2. 行业处于什么阶段，最重要的1到3个变量是什么？
3. 公司是真受益、普通参与者还是概念映射？
4. 利润由销量、价格、成本、利用率、费用或一次性项目如何驱动？
5. 订单、产能和收入确认如何影响未来1到4个季度？
6. 市场当前共识是什么，差异化判断是什么？
7. 未来1周、1个月、3个月、6个月有哪些已知催化剂？
8. 当前市值隐含什么预期，什么估值方法适用？
9. 实控人、质押、减持、解禁、再融资和并购带来什么影响？
10. 股价位置、成交、板块强度和资金类型是否支持当前节奏？
11. 最可能让研究判断失败的三个原因是什么？

完整或深度报告中：

- 财务质量与异常读取 [财务取证](references/financial-forensics.md)。
- 估值、同行与情景读取 [估值政策](references/valuation-policy.md)。
- 输出结构读取 [报告模板](references/report-template.md)。
- 可视化 HTML 读取 [可视化输入契约](references/visual-report-schema.md)。

快速诊断可以缩短内容，但仍需给出公司逻辑、预期差、催化剂、估值方向、风险证伪和数据限制。

### 阶段B：自动补充待核验项

初始判断后，除非用户明确说停止：

1. 提取所有“待核验”“不确定”“数据缺失”和来源冲突。
2. 为每项定向搜索交易所公告、报告、调研记录、订单、股东事件或同行证据。
3. 标记 `已确认 / 仍无法确认 / 修正原判断`。
4. 显式记录修正前后结论及原因。
5. 更新预期差、催化剂、估值和风险置信度。

不能确认的项目保留缺口，不循环搜索或强行闭合。

### 阶段C：技术面证据

读取 [技术面证据边界](references/technical-analysis.md)。有真实、可复核OHLCV数据时，独立分析趋势、量价、关键位和适用的缠论结构；没有精确数据时写“技术面未验证”，禁止估算均线、MACD、支撑压力、中枢、买卖点或关注价位。

基本面和技术面分轴输出：一致时说明共同证据，矛盾时保留矛盾并降低时机信心。技术面不证明基本面正确，基本面也不能替代行情数据。

## 四、核心分析要求

### 业务与行业

- 按产品、客户、地区和商业模式拆分收入利润。
- 写出利润公式和最大弹性变量。
- 识别产业链位置、市场份额、认证、成本、产能、牌照、渠道和治理壁垒。
- 行业景气判断必须落到价格、库存、需求、产能、资本开支、政策或订单等可观察变量。

### 订单与产能

- 核验订单金额、客户质量、毛利率、交付和确认节奏。
- 区分框架协议、意向、送样、认证、中标、正式合同和已确认收入。
- 核验产能、利用率、投放、爬坡、客户锁定和消化风险。

### 预期差与催化剂

必须回答：

```text
市场现在认为它是什么？
证据支持它实际是什么？
差异来自哪里？
什么事件会验证或证伪？
市场是否已经提前定价？
```

没有清晰预期差就直接说。催化剂必须有已知日期或时间窗口；愿望和传闻不能当催化剂。

### 股东、筹码与风险

- 检查最近12个月减持、解禁、质押、监管问询、诉讼、担保和审计变化。
- 资金与技术面只影响市场节奏，不替代经营和估值证据。
- 风险必须写成具体信号、触发条件和对结论的影响。

## 五、同行比较

同行比较不是简单排PE。按估值政策说明样本选择理由，并比较：

- 业务、客户、地区、成长阶段和周期位置。
- 收入利润结构、现金转换、资本强度和治理。
- 估值分母、历史位置和市场隐含预期。

样本不可比或数据口径不一致时降低置信度，不强行排名。

## 六、输出和质量门

### 可视化交付

标准/深度报告在用户要求可视化时，先将已核验的内容映射为 `company-research.json`，再执行：

```bash
python3 scripts/generate_company_research_html.py \
  --input company-research.json \
  --out company-research-{ticker}-{as_of}.html
```

HTML必须显示：研究结论、关键证据台账、业务与利润引擎、催化剂日历、估值与情景、风险与证伪、技术面状态、待核验限制和信息来源。事实、推断、判断使用不同标签；事实带来源与日期；技术面无真实OHLCV时只显示未验证原因。不得将 Markdown 的空白项填成图表、分数或价格。

交付前确认：

- 真正的利润与估值驱动已经识别。
- 当前事实有来源和日期，事实/推断/判断没有混写。
- 财务流量没有累计期重复相加。
- 同行样本和估值模型有适用性理由。
- 情景假设、敏感性和证伪条件已公开。
- 不确定项经过阶段B处理但没有被强行闭合。
- 技术价位全部来自真实数据；无数据就不输出。
- 至少列出三个具体失败原因。
- 可视化 HTML 已通过输入契约、页面脚本和移动端布局检查。

如果结论只是“公司不错、行业空间大、估值合理”，回到边际变化、市场共识、催化剂、现金兑现和证伪条件重新分析。
