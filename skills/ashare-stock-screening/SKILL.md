# A股候选股筛选

本技能只回答：在一个明确股票池和截止日期内，哪些公司通过了用户指定的条件？它不替代单家公司深度研究，也不输出自动买卖、仓位或任意综合评分。

## 一、先固定筛选契约

确认或合理推断：

- `universe`：全A股、沪深300、中证500、某行业或用户列表。
- `as_of`：点时截止日期；默认今天。
- `criteria`：指标、比较符和阈值，例如 `roe_ttm >= 15`。
- `sort` 与 `limit`：按哪个已验证指标排序、保留多少候选。

用户没有给阈值时，先说明可选指标并请用户选择；不要暗中套用“PE小于15”之类的通用标准。跨行业使用 PE、PB、负债率、毛利率、周转天数等阈值时必须提示可比性风险，必要时先按行业分组。

## 二、构造可审计输入

采集或接收数据时读取 [数据契约](references/data-contract.md)。每个参与筛选的指标必须包含：

- 数值与规范单位。
- 期间类型。
- 观察日、发布日期、抓取时间。
- 来源标识、名称和可访问 URL。

优先使用交易所、公司公告、指数公司或可信金融数据服务。数据工具或 Python 库只是传输层；仍要记录其上游来源、接口或版本。不要仅写“来自 AkShare”而丢失原始数据出处。

如果无法为整个股票池取得某个必需指标：

1. 尝试另一可靠来源或缩小股票池；
2. 仍失败时说明缺口；
3. 不得让缺失字段静默通过条件。

## 三、运行确定性筛选器

脚本要求 Python 3.10+，只使用标准库，不自动安装数据依赖：

```bash
python3 scripts/screen_stocks.py \
  --input stocks.json \
  --as-of 2026-08-25 \
  --criterion pe_ttm:lt:20 \
  --criterion roe_ttm:gte:15 \
  --sort roe_ttm:desc \
  --limit 20 \
  --output screening-result.json
```

操作符：`lt`、`lte`、`gt`、`gte`、`eq`、`ne`、`between`。`between` 写成 `metric:between:lower,upper`。

脚本执行以下硬约束：

- `published_at > as_of` 或 `observed_at > as_of` 的证据不可用。
- 缺指标、缺来源、单位错误、日期错误或非数值都会明确排除。
- 所有条件都必须执行；不存在“列缺失所以跳过”的降级。
- 同一输入字节、条件和截止日期产生相同结果与 SHA-256 摘要。
- 排序只使用用户指定指标；不生成隐藏评分。

## 四、解释结果

读取 `screening-result.json`，按照 [输出模板](references/output-template.md) 交付：

1. 筛选范围、截止日期和完整规则。
2. 输入、入选、排除数量及逐层漏斗。
3. 入选候选及每项实际指标、期间、发布日期和来源。
4. 排除原因与缺失统计。
5. 跨行业阈值、样本偏差、数据覆盖和幸存者偏差等限制。

候选排序只代表“更符合这组显式条件”，不代表预期收益更高。若用户要继续研究某家公司，再使用 `ashare-company-research` 分析预期差、催化剂、估值情景、筹码资金和证伪条件。

## 五、质量门

交付前检查：

- 是否真实执行每个条件，而不是只在报告里展示条件。
- 是否保留被排除股票及原因。
- 是否证明所有入选证据在 `as_of` 时已公开。
- 是否标明数值单位和期间类型，避免百分数与小数、TTM与单季混用。
- 是否避免任意评分、单日下跌加分和确定性投资结论。
- 是否能用输入摘要、规则和截止日期复现结果。
