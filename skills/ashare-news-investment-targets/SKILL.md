# 新闻到投资标的提取

本技能用于把新闻链接或文章内容拆成可研究的投资标的池。核心问题不是“这条新闻是不是利好”，而是：

```
这条新闻会不会让市场重新定价某家公司？
```

默认输出中文。默认市场是中国A股；如果用户明确要求港股、美股、可转债、商品或基金，可以按用户指定市场处理。结论要写成研究线索、观察条件和风险证伪，不要写成个性化投资建议。

用户要求“可视化/HTML/研报页面”时，完整流程结束后还应交付自包含 HTML。视觉系统必须与 `ashare-daily-market-review`、`ashare-capital-environment-dashboard` 一致：深墨绿网格背景、宋体研报正文、金色眉题、米白纸张卡、细棕边、5px硬投影、等宽评分与来源元数据。HTML只呈现经核验的新闻、候选、评分和缺口；不得补股票代码、行情、资金、技术指标或价格。

## 一、输入处理

**执行顺序**: 完整流程分三个阶段，自动迭代，不需要用户追问。

**阶段A — 新闻标的提取与评分（步骤一→九）**：
- 步骤一（输入处理）→ 确定新闻原文和来源
- 步骤二至四（判断→分类→传导链）→ 确定新闻是否值得挖、影响路径
- 步骤五（候选池）→ 确定受益/受损标的分层
- 步骤六至七（评分→资金确认）→ 对标的量化排序
- 步骤八至九（输出→质检）→ 结构化交付，标注所有"待核验"项

**阶段B — 前3名标的深度补充（自动触发）**：
- 针对评分表中前3名标的，补充其待核验项（股东减持、订单进展、财务细节等）。
- 如果候选标的不足3个，则对全部候选标的执行深度补充；如果只有1个标的，则按单标的处理。
- 更新评分和结论。

**阶段C — 前3名标的技术面分析（subagent执行）**：
- spawn独立子agent对前3名标的逐一执行技术面分析（趋势跟踪+缠论）；不足3个时分析全部标的。
- 整合技术面结论进最终观察计划。

> 🔴 **CHECKPOINT 流程控制** — 阶段A交付后，不要停下来问用户"是否继续"。直接告知"接下来对评分前3名标的进入深度补充和技术面分析"；如果不足3个，说明将分析全部候选标的，然后自动执行阶段B和C。只有当用户明确说"先这样"或"够了"时才停止。

用户可能提供：
- 新闻链接、公告链接、研报链接或网页链接。
- 直接粘贴的文章、新闻、公告、纪要、研报摘录。
- 多条新闻列表。
- 一个主题方向，例如“昨晚美股人工智能大涨，映射哪些A股”。

处理规则：
- 如果用户给链接，并且可以联网或打开网页，先读取原文，记录来源、标题、发布时间和访问时间。
- 如果链接无法访问，要求用户粘贴正文；不要根据标题硬猜。
- 如果用户粘贴文章，先提取标题、时间、来源、核心事实；如果缺失，标记为“未提供”。
- 如果新闻涉及实时行情、最新公告、股价位置、资金流向，必须核验最新数据；无法核验时要明确写”待核验”。

### 输入处理异常

| 触发条件 | 一线修复 | 仍失败兜底 |
|----------|----------|-----------|
| 搜索工具无法获取新闻原文 | 换用其他搜索工具；尝试搜索新闻标题+来源关键词 | 要求用户粘贴正文；标注”原文未能获取，以下分析基于[标题/摘要]” |
| 新闻来源不可靠（自媒体、匿名论坛、营销号） | 搜索是否有权威媒体跟进报道 | 标注”来源可信度较低”，结论降级为”待权威来源确认” |
| 用户只给一个词或极简输入（如”看看低空经济”） | 先搜索该主题的最新重大新闻，找到后按正常流程处理 | 告知用户”需要具体新闻或事件才能提取标的，请提供链接或文章” |
| 多条新闻互相矛盾 | 优先采信交易所公告、官方发布、权威媒体 | 列出矛盾点，按各来源分别建传导链，让用户判断 |
| 用户给的是旧闻（发布时间>1周前） | 搜索是否有后续进展或最新同类新闻 | 标注”该新闻已超过1周，市场可能已充分反应”，评分中预期差维度封顶5分 |

## 二、先判断新闻是否值得挖

先不要急着列股票。先判断新闻能否形成短传导链：

```
新闻事件 → 行业变量 → 公司收入/成本/订单/估值 → 股价
```

链条越短，短线价值越高。

优先关注强关联新闻：
- 产品涨价。
- 大订单或大客户突破。
- 政策补贴、财政资金、招标落地。
- 供给受限、库存下降、价格上涨。
- 海外龙头大涨或财报超预期，并能映射到A股产业链。
- 行业数据连续改善。
- 技术突破进入量产、送样、认证或订单阶段。
- 并购重组、资产注入、股权激励、回购或增持。

谨慎处理弱关联新闻：
- 纯宏观口号。
- “行业空间很大”但缺少短期兑现。
- “公司布局某概念”但收入占比很小。
- 只是名称、概念或题材相关，无法影响收入、利润、订单或估值。

> 🔴 **CHECKPOINT 1 · 新闻值得挖吗** — 如果新闻属于弱关联且无法建立短传导链（新闻→行业变量→公司业绩→股价），🛑 STOP 并直接告诉用户"该新闻短线投资价值有限，不建议展开"，不要强行凑标的。

## 三、新闻分类

先把新闻归入一类或多类：政策类、行业数据类、价格变化类、公司公告类、订单类、业绩类、海外映射类、技术突破类、资金类、风险类。

不同类型处理重点：

| 类型 | 重点看什么 |
|------|-----------|
| 政策类 | 钱流向哪里、项目给谁、订单给谁、谁最先兑现 |
| 价格类 | 产品涨价、成本下降、产能规模、利润弹性 |
| 订单类 | 订单占营收/市值比例、客户质量、毛利率、交付周期 |
| 海外映射类 | A股供应商、替代品、设备材料、零部件 |
| 行业数据类 | 环比改善、连续改善、市场之前是否悲观 |
| 技术突破类 | 按”已量产→已送样→已认证→实验室突破→概念储备”排序 |
| 资金类 | 机构调研、龙虎榜、北向、融资、回购、增持、板块成交 |
| 风险类 | 不要只找受益方，也要找受损方和需要回避的公司 |

## 四、建立传导链

每条新闻必须回答五个问题：

1. 这条新闻影响哪个行业变量？
2. 这个变量影响收入、成本、订单、估值，还是风险偏好？
3. 哪些上市公司最直接受益或受损？
4. 市场之前是否已有预期？
5. 股价和资金是否已经提前反应？

如果这五个问题答不上来，就不要强行推荐标的。

## 五、建立候选标的池

按受益程度分层，不要只列一个公司。

分为：
- 一级受益：收入、利润、订单或估值框架直接受影响。
- 二级受益：订单可能增加，产业链间接受益，验证还不充分。
- 三级概念：业务或题材相关，但业绩贡献不确定。
- 伪受益或风险标的：名字相关、概念相关但业务不相关，或新闻反而带来风险。

每个候选标的必须写清：
- 公司名称和代码。
- 所属环节。
- 受益逻辑。
- 需要核验的数据。
- 与新闻的证据链。
- 是否已经被市场交易。

不要编造股票代码。无法确认代码时，用公司名称并标记”代码待核验”。

> 🔴 **CHECKPOINT 2 · 候选池充分性** — 进入评分前核验：至少有1个一级受益标的，且每个标的都有明确的受益逻辑（不是”概念相关”）。如果全部候选都是三级概念，🛑 STOP 并向用户说明”该新闻当前只能找到概念级标的，建议等待更明确的产业落地信号”。

## 六、评分模型

对每个候选标的使用100分评分。详细口径见引用资料中的评分细则。

评分维度：

| 维度 | 分数 |
| --- | --- |
| 新闻强度 | 20 |
| 关联强度 | 20 |
| 预期差 | 15 |
| 业绩弹性 | 15 |
| 股价位置 | 10 |
| 板块强度 | 10 |
| 资金痕迹 | 10 |

分数解释：

| 总分 | 结论 |
| --- | --- |
| 80分以上 | 重点研究，可能进入交易池 |
| 65到80分 | 加入观察池 |
| 50到65分 | 只观察，不急 |
| 50分以下 | 暂时放弃 |

如果股价位置、板块强度或资金痕迹没有实时数据，不要胡乱打高分；可以给”待核验分”并说明缺口。

**无实时数据时的降级评分规则**：

股价位置、板块强度、资金痕迹三项合计30分。无法获取实时数据时：不要给中性分敷衍——每项给”待核验”按0分计入，总分按满分70分换算（`调整后总分 = 实际得分 / 70 × 100`），输出标注”含30分待核验项，按70分口径换算”。

## 七、技术面和资金确认

新闻给逻辑，板块给情绪，技术面给买点，资金面给确认。

优先识别：
- 新闻前3到5天温和放量。
- 低位横盘后放量突破。
- 回调缩量且不破关键位置。
- 板块放量，龙头强势，跟风扩散。
- 机构调研、龙虎榜、融资余额、北向、回购或增持形成确认。

谨慎识别：
- 新闻当天才高开冲板。
- 高位爆量长上影。
- 利好后高开低走。
- 板块强但个股弱。
- 利好越来越多但股价涨不动。

## 八、输出结构

完整分析使用引用资料中的输出模板。交付分三个阶段：

### 阶段A输出（新闻标的提取与评分）

快速输出至少包含：
1. 新闻一句话结论。
2. 影响路径。
3. 候选标的分层表。
4. 标的评分表。
5. 前3名标的的机会与风险；不足3个时覆盖全部标的。
6. 需要核验的数据清单。
7. 观察计划和证伪条件。

交付后**标注所有"待核验"项**，并告知用户"接下来对评分前3名标的进入深度补充和技术面分析"；不足3个标的时说明将覆盖全部标的。

### 阶段B输出（前3名标的深度补充）

以"前3名标的待核验项深度补充"为标题，按标的逐项列出：
- 核验结果（已确认/仍无法确认/修正原判断）
- 来源和日期
- 对评分的影响
- 更新后的评分表（如有变化）

### 阶段C输出（前3名标的技术面分析）

由子agent独立输出，包含：
- 趋势跟踪结论（方向+强度+关键位+操作建议）
- 缠论结论（走势结构+中枢+买卖点+操作建议）
- 两体系一致性判断
- 具体关注价位（买入观察/止损/止盈参考）
- 与新闻逻辑的一致性/矛盾分析

主agent将技术面结论整合进最终观察计划。

### 可视化 HTML（完整结果或用户明确要求时）

读取 [可视化输入契约](references/visual-report-schema.md)，将已核验的新闻、候选池、评分、深度补充、技术面状态、观察计划、缺口和来源写入 `news-targets.json`，再执行：

```bash
python3 scripts/generate_news_targets_html.py \
  --input news-targets.json \
  --out news-targets-{as_of}.html
```

缺实时数据的评分项必须在 HTML 中标为待核验并按0分换算；技术面没有真实OHLCV与复权口径时，只能显示“技术面未验证”和原因。不能把新闻标题、概念关联或 Markdown 空白项渲染成图表、价格或买卖建议。

## 九、质量检查

> 🔴 **CHECKPOINT 3 · 输出门控** — 交付前必须通过以下检查。任何一项不通过，回到对应章节补充，不要交付空洞的"利好某某板块，相关公司有A、B、C"。

交付前检查：
- 是否提取了新闻的增量信息，而不是复述标题。
- 是否说明了新闻影响的行业变量。
- 是否把受益公司分成一级、二级、三级和伪受益。
- 是否说明了每个标的的证据链，而不是只列概念股。
- 是否使用100分模型打分。
- 是否标记了“已验证”和“待核验”。
- 是否判断市场是否已经定价。
- 是否写出后续催化和证伪条件。
- 是否避免把个人投资建议写成确定性买卖指令。

如果输出只是”这条新闻利好某某板块，相关公司有A、B、C”，说明不够。必须把新闻拆成产业变量、业绩或估值传导、市场预期、资金确认和风险证伪。

## 十、阶段B：前3名标的深度补充（自动触发）

阶段A交付后，**不要停下来**。从评分表中取前3名标的，对其待核验项发起定向搜索补充。候选标的不足3个时，对全部候选标的执行深度补充；只有1个标的时按单标的处理。

### 为什么默认深度补充前3名

新闻标的提取可能产生5-10个候选。默认对评分前3名做深度补充，可以覆盖最强主线、潜在弹性标的和备选验证对象；其余标的留在观察池即可，用户如需进一步研究可手动指定。

### 执行步骤

1. **确定深度研究对象**：按评分表从高到低取前3名；不足3个时取全部候选标的。若分数并列导致第3名边界不清，可纳入并列标的，但必须说明原因。
2. **收集前3名标的的待核验项**：从阶段A报告中提取这些标的所有”待核验””不确定””需进一步验证”的数据。
3. **逐项定向搜索**：对每个待核验项设计精准搜索关键词，并行搜索。常见待核验项搜索策略：

| 待核验类型 | 搜索策略 |
|-----------|----------|
| 股东减持进展 | “公司名+减持+结果+年份”，查交易所公告 |
| 最新订单/签约 | “公司名+订单/签约/合作/中标+年份” |
| 机构调研 | “公司名+机构调研+年份”，查投资者关系活动记录 |
| 业务进展（新业务/海外/具身智能等） | “公司名+业务关键词+合约/订单/进展” |
| 券商研报和盈利预测 | “公司名+研报/目标价/盈利预测” |
| 行业政策试点参与 | “政策关键词+公司名”，查试点名单 |

4. **更新结论**：已确认的标注来源；仍无法确认的说明影响权重；修正原判断的显式写出变化。
5. **更新评分**：如果补充验证后预期差或业绩弹性维度显著变化，重新评分并写明理由。
6. **输出补充报告**：以”前3名标的待核验项深度补充”为标题交付，按标的分段输出。

> 🔴 **CHECKPOINT 4 · 深度补充完成** — 待核验项全部处理完毕后，展示更新摘要，然后自动进入阶段C技术面分析。

## 十一、阶段C：前3名标的技术面分析（subagent执行）

深度补充完成后，**spawn独立子agent**对前3名标的逐一执行技术面分析。不足3个标的时覆盖全部标的。

### 子agent执行指令

使用Agent工具spawn子agent，prompt模板如下：

```
你是一个A股技术面分析专家。请对以下股票进行技术面分析，覆盖两个体系：

**股票**：[前3名标的公司名称和代码，逐一分析]
**当前股价**：[从阶段A/B获取的最新股价，按标的分别列出]
**分析周期**：日线为主，参考周线

**体系一：趋势跟踪分析**

必须覆盖：
1. **趋势方向判断**：当前处于上升趋势/下降趋势/震荡，判断依据（均线排列、高低点关系）。
2. **关键均线位置**：5日、10日、20日、60日、120日、250日均线的当前值和股价与均线的位置关系。
3. **趋势强度**：均线是否发散/收敛/粘合，成交量是否配合趋势。
4. **支撑位和压力位**：最近的3个支撑位和3个压力位，标注来源（均线/前期低点/成交密集区/缺口）。
5. **趋势信号**：最近是否出现金叉/死叉/均线突破/跌破，以及对应的成交量确认。
6. **MACD状态**：DIF和DEA位置、红绿柱变化、是否出现顶背离/底背离。

**体系二：缠论分析**

必须覆盖：
1. **K线包含处理**：描述最近的包含关系处理结果。
2. **分型识别**：最近出现的顶分型和底分型位置。
3. **笔的划分**：当前从最近一个端点到另一个端点的笔的走势。
4. **线段判断**：当前线段的方向和是否可能出现线段转折。
5. **中枢位置**：最近一个中枢的区间[ZD, ZG]，以及当前价格与中枢的关系。
6. **背驰判断**：是否出现趋势背驰或盘整背驰的信号。
7. **买卖点定位**：当前是否处于一买/二买/三买或一卖/二卖/三卖的区域附近。

**最终输出**：
- 趋势跟踪结论：当前趋势方向+强度+关键位+操作建议（多头持有/观望/等待回调/回避）。
- 缠论结论：当前走势结构+中枢位置+买卖点级别+操作建议。
- 两个体系的结论是否一致。如果矛盾，说明可能的解释。
- 具体的关注价位：买入观察价、止损价、止盈参考价。

```

### 整合规则

子agent返回技术面结论后，主agent整合：
1. **技术面与新闻逻辑一致**（新闻利好+技术面趋势向上）→ 强化观察计划，提供具体入场价位。
2. **技术面与新闻逻辑矛盾**（新闻利好但技术面趋势向下/高位滞涨）→ 必须写出矛盾说明，建议等待技术面确认后再考虑。
3. 技术面的关键价位整合进最终观察计划的”关注条件”和”证伪条件”。

> ⚠️ 技术面分析不改变新闻逻辑的方向判断，只影响节奏和入场时机。新闻驱动型机会的节奏通常比纯基本面研究更快，技术面确认的重要性更高。

交付前逐条对照，任何一条命中则输出质量不达标。

| # | 反模式 | 正确做法 |
|---|--------|----------|
| 1 | **只列概念股不建传导链** | 每个标的必须回答：新闻通过什么变量影响这家公司的收入/利润/订单 |
| 2 | **评分全是高分，无区分度** | 一级受益与三级概念的评分差距应在20分以上 |
| 3 | **根据标题硬猜内容** | 要求用户粘贴正文；否则标注”基于标题推测，可能不准确” |
