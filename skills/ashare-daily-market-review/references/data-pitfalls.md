# 每日复盘实测口径与避坑清单

本文件收纳运行 `ashare-daily-market-review` 时踩过的真实口径问题。**每次跑之前至少扫一遍第一节「最高频条目」。**

来源标注了沉淀日期，供判断是否已被上游修复。新增经验请按主题追加到对应小节，不要写回 SKILL.md 正文——SKILL.md 是操作手册，这里才是经验库。

---

## 一、最高频条目（每次必看）

1. **采集通道故障 ≠ 数据缺失**（2026-09-10）。走代理时 `push2.eastmoney.com` 会高频返回 `ProxyError / RemoteDisconnected`，此时先换备用主机并串行长重试，**不要直接判 unknown**。
2. **不同来源的涨停家数不能互认**（2026-08-29、2026-09-10）。东财涨停池不含 ST，财联社盘后统计口径也不同；即使方向一致也不能当作同一股票池。
3. **滚动均值窗口必须显式声明**（2026-09-10）。取 20 日均值时数据长度不足会被静默算成更短窗口，数值偏小且不易察觉。
4. **跌停池必须带 `sort=fund:asc`**（2026-09-11）。参数不对时不会报错，只会静默返回空池——见第二节「跌停池接口参数」。
5. **全A宽度翻页必须 `pz=100`**（2026-09-14）。`pz=500` 会让翻页提前中断，把 `decliners` 静默算成 0，不报错、只出错数——最危险的失败方式。翻完必须自检 `上涨+下跌+平盘 ≤ 有报价样本`。
6. **写 `deep_analysis` 前先过 1.5 四条纪律**（2026-09-17）。催化逐条给 `scope/catalyst_type/transmission`（宏观事件走 `macro_backdrop` 且不绑主题）、`security_details.cross_check_tolerance_pct` 必填且 1 日窗口要对上基础章节口径、集中度要么 `complete` 要么显式 `sample`+覆盖率。**校验器会拒收，不是提醒。**

**跌停家数不可跨源比较**（2026-09-14）：2026-09-11 同一交易日，开盘啦口径跌停 5 只、东财跌停池 21 只。跨源比较会得出完全相反的方向结论，详见第十节。

## 二、股票池口径

### 涨停家数供应商差（2026-08-29、2026-09-10）

- 腾讯自选股 `data_changedist`（全样本含 ST）与财联社盘后统计（不含 ST/退市）存在差异。
- 实测 2026-09-10：东财涨停池 `tc=35`，财联社盘后统计 39~40。
- **即使差异不改变某次阈值结果，也不能把两个股票池声明为完全一致。** `short_term_sentiment` 最多标 `partial` 并输出 unknown，或改采同一股票池的完整数据。
- 报告须写清采用哪一套，并保持宽度与情绪同源。

### 东财涨停/炸板/跌停池不含 ST（2026-09-10）

- 实测当日池内 0 只 ST，而 ST龙元 +10.19%、*ST宝馨 +10.05% 均未入池。
- 但指数级涨跌家数 `f104/f105/f106`（上证指数/深证成指/北证50）**含 ST 与风险警示股**。
- 两者不能声明为同一股票池。

### 重建同池宽度的可行做法（2026-09-10）

用 `push2delay` 的 `clist/get` 分页枚举全 A：

```
pz=100，约 56 页，每页 ≈0.5s
```

再按名称剔除含 `ST` / `*ST` 的个股，即得到与涨停池一致的非 ST 股票池。

- ⚠️ `fs` 里的 `f:!2` 实测**并未**剔除 ST，必须另行按名称过滤。
- 实测 2026-09-10 全样本枚举得 955 涨 / 4512 跌 / 84 平，与财联社收评完全一致，可作交叉校验锚点。

### 封板尝试次数反推（2026-08-29）

财联社披露炸板数与封板率时：

```
limit_attempts = 涨停数 + 炸板数   （必须同一来源同一口径）
```

勿用「最终涨停家数」替代分母。

### 炸板率分母（2026-09-10）

```
炸板率 = 炸板池tc / (涨停池tc + 炸板池tc)
```

2026-09-10 为 22/57 = 38.60%，与新闻口径 37% 有差（分母不同），**不强行对齐**。

### 跌停池接口参数（2026-09-11）

`getTopicDTPool` 对 `sort` 参数敏感，**三种参数只有一种可用**：

| 参数 | 返回 |
|---|---|
| 不带 `sort` | `{"rc":102,...,"data":null}` —— 直接无数据 |
| `sort=fbt:asc` | `tc=21` 但 `pool=[]` —— **最危险：有家数没明细，不报错** |
| `sort=fund:asc` | `tc=21` + 21 条完整明细 ✅ |

涨停池 `getTopicZTPool` 与炸板池 `getTopicZBPool` 用 `sort=fbt:asc` 正常。**校验方式**：拿到池后必须核对 `tc == len(pool)`，不等即参数有误。

### 全A枚举的样本构成与「定转」（2026-09-11）

`fs=m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23,m:0+t:81+s:2048` 返回 5,913 条，构成如下：

| 类别 | 数量 | 处理 |
|---|---|---|
| 沪主板 6xxxxx | 2,467 | 保留 |
| 深主板 0xxxxx | 1,641 | 保留 |
| 创业板 3xxxxx | 1,450 | 保留 |
| 北交所 920xxx | 349 | **保留**（属沪深京口径） |
| 北交所 8xxxxx（833994/833874/832317） | 3 | 保留 |
| `810xxx` 「定转」 | 6 | **必须剔除**：北交所定向可转债，不是股票 |
| 无沪B(900xxx)/深B(200xxx) | 0 | — |

剔除「定转」并按名称过滤 ST 后：非ST有报价 **5,352** 只，非ST无报价（`f2`/`f3` 均为 `-`，含退市/长期停牌/未上市）**235** 只。

⚠️ 旧记录写「另有19只停牌无成交」是更窄的口径；本口径下无报价样本达 235+ 只（含中国北车、海通证券等已退市/已吸收合并的老代码），**两个数字不可直接比较**。

### 新闻锚点用「含ST全样本」，报告用非ST（2026-09-11）

- 东财枚举的**含ST全样本** 643 涨 / 4,870 跌 / 40 涨停 / 21 跌停，与中国证券报当日收评（「上涨643只、40只涨停、4870只下跌、21只跌停」）**逐项完全一致**，是最可靠的交叉校验锚点。
- 报告 `breadth` 用的是**非ST口径**（593 / 4,723 / 36），对应 `universe=all-a-non-st-cn`。
- 两套口径都要在 `status_reason` 里写明并标明「不作混用」，**不要把含ST的数字填进 breadth**。

## 四、成交量与滚动指标

### 5 日 / 20 日均值口径（2026-08-29、2026-09-10）

- 用上证指数 + 深证成指指数 K 线 `amount` 加总近似（**不含北交所**），口径写入 `status_reason`。
- ⚠️ `lmt=15` 会把 20 日均值静默算成 15 日均值。取 5/20 日均值时 **`lmt` 至少 25**，并显式写 `window.trading_days`。
- 不要用短期窗口的数值充当更长窗口的均值——数值偏小且不易察觉。

### 前一交易日成交额核验（2026-08-29）

`data_quote` 的历史日期参数可取前一交易日收盘，用于 `previous_amount` 核验。

## 五、资金数据

### 两融滞后（2026-08-29）

`data_market_overview type=margin` 的 row 常为空（仅 schema）。当日复盘若两融未发布，标 `partial`，或改用证券时报数据宝 WebSearch。

### 两融 T+1 盘后修订模式（2026-09-11）

- close 快照只能拿到 T-1 两融（当日盘后尚未披露），`funds` 标 partial 是设计内状态。
- **次日上午 9-10 点后** `RPTA_RZRQ_LSHJ` 即可取到 T 日两融数据，可做一次 `post_close` 修订：以 r001 输入为基底仅更新 funds 章节（observed_at → T 日），snapshot 改 `type=post_close`、`revision+1`、`supersedes_sha256` 指向上一修订输入 SHA、`as_of` 改为当日。
- 修订时 **funds item 名称同步去掉“（T-1）”后缀**，避免报告出现“融资净买入（沪深两市，T-1）观察日=当日”的口径矛盾。
- 拷贝 r001 输入构造修订基底时，**用 `json.dumps` 深拷贝再改**，不要原地复用 dict；生成后 grep 检查无残留脏键（2026-09-11 实测踩坑：r002 曾混入 `observed面at` 脏键，被迫 r003 修正）。

### 周五两融在周末拿不到（2026-09-11）

2026-09-12（周六）14:20 查询 `RPTA_RZRQ_LSHJ` 的 `2026-09-11` 行，返回 `{"success":false,"message":"返回数据为空","code":9201}`，最新仍为 09-10。即**周五交易日的两融要等下一交易日（周一）才会补齐**。

结论：周末复盘周五盘面时，`funds` **必然**是 `partial` + T-1 口径，不是采集失败。`status_reason` 要写「9月11日两融截至采集时点尚未发布，属T+1披露而非数据缺失」。

### 北向数据已断供（2026-09-10）

`push2his .../kamt.kline/get` 返回逐日相同常量（0.00 或固定值），**不可当作净流入使用**。funds 章节只保留交易所两融事实，其余标 `partial` 并说明原因。

### method_category 门禁（2026-08-29）

- 仅有供应商模型或活跃度代理时，funds 不能标 `available`。
- 北向成交额不是方向性净流入，不能作为资金方向证据。

### 个股多周期资金流字段语义（2026-09-14 实测校正）

东财 `f62/f267/f164/f174` 的**真实窗口**与常见转述不一致，实测校正如下：

| 字段 | 真实语义 | 实测校验方式 |
|---|---|---|
| `f62` | 今日主力净额 | 与外部复盘披露的「今日主力」逐项一致 |
| `f267` | **3 日**主力净额 | 日线 `f52` 近 3 日累加 −9.74 / −30.52 / +1.70 亿，三只票全中 |
| `f164` | **5 日**主力净额 | 日线近 5 日累加 +6.57 / −31.21 / +1.74 亿，三只票全中 |
| `f174` | 10 日主力净额 | 与外部复盘披露的「10 日主力」逐项一致 |

⚠️ **易错点**：把 `f267` 当成 5 日、`f164` 当成 10 日。2026-09-14 实测的一份外部复盘报告就把 `f267` 标成了「5日主力」。**写入报告前必须标注清窗口**，不要把 3 日数据写成 5 日。

取数口径：

- **快照**：`push2delay.eastmoney.com/api/qt/ulist.np/get?secids=…&fields=f12,f14,f62,f267,f164,f174` —— 稳定、可批量。
- **历史**：`push2his.eastmoney.com/api/qt/stock/fflow/**kline**/get`（`fields2=f51,f52`，`klt=101`，`lmt`≥15）。**注意是 `kline` 不是 `daykline`**：`fflow/daykline/get` 在本机多次直接 `RemoteDisconnected`，而同主机 `fflow/kline/get` 一次成功并返回 15 行。
- `push2delay` 的 fflow 系列（含 `kline`/`daykline`）**只返回最新 1 天**，拿不到历史；历史必须走 `push2his`。
- `push2his` 对密集请求限流明显：连续请求约 6~8 次后开始持续 `RemoteDisconnected`。批量取历史时**串行 + 每次间隔 ≥1s**，被限流后需要冷却数十秒而非立刻重试。

## 八、板块口径与快照类型（2026-09-11）

### 东财板块 ≠ 申万官方一级指数

板块用 `push2delay .../clist/get?fs=m:90+t:2` 拉全量后，按 `BK1200-BK1217 / BK0427 / BK0433 / BK0436-BK0438 / BK0456 / BK0464 / BK0478 / BK0479 / BK0486 / BK0728 / BK1035 / BK1283` 这 30 个码过滤，得到 30 个「申万一级同名板块」（东财口径，缺「综合金融」）。

**同名不等于同值**，实测 2026-09-11：

| 板块 | 东财板块口径 | 申万官方指数（新闻披露） |
|---|---|---|
| 通信 | -0.04% | +1.41% |
| 有色金属 | -3.12% | -3.98% |

原因是成分与权重口径不同（申万为自由流通市值加权指数）。处理原则：

- **逐日固定用同一套**（当前基线为东财口径），保证跨日可比；
- `status_reason` 里显式写明口径差异并给出示例，**不要试图与新闻数值对齐**；
- 排序只在本体系内做，禁止行业/概念/地域混排。

### 周末复盘用 `weekend_update`

周六/周日生成"周五盘面"复盘时：

- `market_date` = 周五（最近交易日），`as_of` = 当天（周六/周日）；
- `snapshot.type = weekend_update`，`cutoff_at` 取当天时间且带时区；
- 周末新公开的事件可以进 `events`（`published_at` 不晚于 `cutoff_at`）；
- `close` 类型只能用于「截止日 == market_date」的场景，**不可用于周末补做**。

### 20/60 日分位依赖本地历史积累

`--history-dir` 里只有 2 个交易日时，摘要的 20/60 日分位会显示「样本不足」——这是诚实输出而非缺陷。**想让分位可用就必须每天带着 `--history-dir` 跑**，中断会让分位长期停在"样本不足"。

## 九、1.2 分析层：主线矩阵与延续性检验（2026-09-14）

本节的规则来自一次外部高分复盘的横向比对：对方在「判断穿透力」上明显更强，但它不可复现、口径靠人工注释。1.2 的做法是把那些判断**改写成可复算的结构**，而不是照搬结论。

### 「双确认」是结构分类，不是入场信号

外部复盘用「游资情绪面 × 机构资金面」四象限判主线，这个方法本身有效，但措辞天然像荐股。落进本技能时：

- 象限一律称「结构分类」，报告里显式写「不是评分，不构成入场信号或仓位指令」；
- 阈值由输入显式声明（`quadrant_rules`），**不允许**在代码里留隐藏默认值——这正是「不得有隐藏总分」的同一原则；
- 四象限不合并成任何单一数字。

### 板块资金流必须带方法类别

- `sectors.items[].fund_flow` 与 `fund_flow_method_category` 必须同时出现，否则拒绝。
- 板块主力净流入几乎都是 `provider_model`（东财 `f62` 类字段），**不是**交易所事实，报告按类别披露。
- 不要把资金净流入和成交额活跃度互换：后者是 `activity_proxy`，方向性有限。

### 主题归组是人工的，必须留 caveat

- `mainline_matrix.themes[].boards` 引用 `sectors.items[].id`，引用悬空直接报错。
- 主题成分是**人工归组**，同一只票可能落进多个主题 → 在 `caveat` 里写明，别让读者以为是原生板块。
- 任一声明板块缺 `fund_flow` 时，该主题象限返回 `unknown` 并在 `missing_board_fund_flow` 列出缺口；**不得**用 0 或部分求和冒充。
- 多板块时板块涨跌幅取**等权均值**，且必须标注「等权」——不做自由流通市值加权，避免引入第二个口径。

### 晋级率的健康线要显式声明

- `prev_pool_performance.health_threshold_pct` 未声明时只输出晋级率、**不作**高于/低于判断（2026-09-14 实测：外部报告用 30% 作健康线，属于该报告的自设口径，不能当成行业标准）。
- `universe` 必须与 `breadth.universe` 结构化一致；前一交易日涨停池和当日宽度不同池时，晋级率没有可比性。
- `promotion_count` 不得大于 `pool_size`（实测这道断言拦住了手工填数的笔误）。
- `previous_market_date` 必须严格早于 `market_date`。

### 阈值体检不聚合成分数

- `health_thresholds` 是**可选**的；不声明就不体检，绝不回退到隐藏默认值。
- 统一单调：`*_min` 用 `>=`，`*_max` 用 `<=`，不做例外。
- 缺观察值（例如没给 `prev_pool_performance`）列入 `unresolved`，不计入 `evaluated_count`，也不算失败。

### 700 行上限会逼你继续拆模块

`make audit` 的 `MAX_SCRIPT_LINES = 700` 是硬门。加完 1.2 后 `validate/derive/render` 三个模块一起超标，正确做法是**继续拆**而不是调高阈值：

- 通用证据断言下沉到 `evidence.py`，顺带解掉了 `validate.py ↔ validate_analysis.py` 的循环导入；
- 1.2 的校验/派生/渲染各自独立成模块；
- 格式化助手抽到 `formatting.py` 供两个渲染模块共用。

**经验**：加功能前先估行数；`validate.py` 一度只剩 121 行余量，再堆两个章节必然破线。

## 十、真实盘面回填实测（2026-09-14）

用 9/14 真实收盘数据把 1.2 分析层跑通一次后新增的坑，全部为当日实测。

### 取数通道：分页与限流

- **全A宽度必须 `pz=100` 逐页翻**。`pz=500` 时 `data.total` 与实际返回条数对不上，会在翻到一半时提前 `break`，把 `decliners` 静默算成 0（本次实测踩到，差点把 3126/2224 写成 1100/0）。翻到底为止，并核对 `上涨+下跌+平盘 ≤ 有报价样本`。
- **无报价（停牌/退市）个股的 `f3` 不是数值**，不计入分母；有报价样本数会随复牌变化，报告里写明样本数。
- **行业板块资金流**用 `fs=m:90+t:2` + `fid=f62`：降序（`po=1`）取净流入 Top，**升序（`po=0`）取净流出 Top**——只取降序会以为全市场资金净流入。`pz` 上限 100，要翻页。
- **`push2his` 密集请求会整体限流**：`push2his.eastmoney.com` 与 `1..N` 编号备用主机**全部** `RemoteDisconnected`，此时 `push2delay` 的同名 kline 端点返回 0 行，**不能顶替**。兜底只有两条——复用当日已成功落盘的 K 线，或等冷却。
- **行业板块列表同时含二级与三级**（`电子化学品Ⅱ`/`电子化学品Ⅲ`、`调味发酵品Ⅱ`/`Ⅲ`），且数值完全相同。主题归组引用时**只取一个**，两个都引用会把板块资金翻倍。
- **两融 T+1 可取最近披露日**：`datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPTA_RZRQ_LSHJ`（`sortColumns=DIM_DATE&sortTypes=-1`）。字段 `RZYE` 融资余额 / `RQYE` 融券余额 / `RZJME` 融资净买入。9/14 盘后拿到的最新披露日是 9/11，写成 `observed_at=2026-09-11` 并注明 T+1。

### 跌停家数跨源会得出反向结论

2026-09-11 跌停：开盘啦口径 **5** 只，东财跌停池口径 **21** 只；9/14 两个口径同为 16 只。

→ 「跌停从 5 扩到 16」与「跌停从 21 缩到 16」是方向完全相反的两句话。**跨源比较跌停家数没有意义**；必须锁定单一池（本技能锁东财跌停池）并在证据里标注来源。

### 象限阈值必须表达强度，不能填 0

同一份 9/14 数据跑两种阈值（涨停门槛都是 3）：

| `capital_threshold_cny` | `dual_confirmed` 个数 | 与人工定性一致 |
|---|---:|---:|
| 0（只看净流入符号） | 6/10 | 6/9 |
| 11 亿元 | 4/10 | 8/9 |

阈值填 0 时，板块资金 **+0.83 亿** 的汽车链与 **+28.84 亿** 的 PCB 链落进同一格，「双确认」直接丧失信息量。

而且象限对阈值**敏感且不连续**：消费·食品板块资金 +11.45 亿，刚好越过 11 亿门槛就变 `dual_confirmed`。所以阈值本身就是研究判断，必须显式声明并可复盘（`quadrant_rule` 写进报告，正是为此）。

### `sentiment_only` 语义重叠 → 已拆出「情绪失血」（2026-09-14 落地）

涨停家数达标但资金大额净流出的板块，与「家数多、资金弱正」的板块原本落进**同一个 `sentiment_only`**，标签丢掉了资金方向：

| 主题 | 涨停 | 板块资金 | 拆分前 | 拆分后（失血线 `-50 亿`） |
|---|---:|---:|---|---|
| AI应用·AI安全 | 11 | +10.02 亿 | `sentiment_only` | `sentiment_only`（情绪脉冲） |
| 光模块·光通信 | 6 | **-72.61 亿** | `sentiment_only` | **`sentiment_bleeding`（情绪失血）** |

根因：情绪轴是纯家数阈值，无法区分「家数达标 + 资金流入」与「家数达标 + 大额流出」。

已落地的做法：给 `quadrant_rules` 加**可选键** `bleeding_threshold_cny`，把该格按资金流出深度拆成「情绪脉冲 / 情绪失血」。约束：

- 失血线必须**严格小于** `capital_threshold_cny`（否则「资金先行」与「情绪脉冲」的判定区间倒挂/重叠），校验直接拒收；`quadrant_rules` 只接受 `limit_up_threshold / capital_threshold_cny / bleeding_threshold_cny` 三个键。
- **不声明该键时行为完全不变**：`sentiment_bleeding` 不参与计数、不进图例、不产出信号、不出现在摘要任何字段，报告与摘要逐字节一致。真源见 `schema.active_quadrant_order`。
- 失血线是研究判断（沿用上述「阈值即判断」原则），必须显式声明并写进 `quadrant_rule`。

### 体检阈值表达不了「同题材连板共振」

`health_thresholds` 的五个键（涨停下限 / 跌停上限 / 炸板率上限 / 晋级率下限 / 最高板下限）覆盖不了「≥3 只同题材连板」这类**跨主题结构**条件。实测外部报告的 4 条情绪阈值只能复现 3 条（得 1/3 而非 1/4）。缺的项如实标注为覆盖缺口，**不要硬凑条数**。

### 晋级率已可结算

`promotion_rate_pct` 进入 `VERIFICATION_METRICS` 后，以 `event_date` 当天的同一口径自动结算。实测：9/11 涨停池 40 只 → 9/14 再涨停 11 只 = **27.50%**，条件 `>= 30` 判为未成立，并已进入「连续历史」指标表。

两个约束要记住：该指标**只在输入声明了 `prev_pool_performance` 时**才出现在指标集合里（旧输入的报告与摘要保持逐字节不变）；`unit` 必须配 `percent`。

## 十一、一键取数工具 `tools/fetch_daily_market.py`（2026-09-14）

仓库根目录提供取数工具，把 9/14 的手工脚本泛化成日用命令：

```bash
make fetch-market DATE=2026-09-14 OUT=market.json CTX=ctx.json
# 等价：python3 tools/fetch_daily_market.py --date 2026-09-14 --out market.json --context ctx.json
```

**自动抓取**（东财一手）：indices / breadth / short_term_sentiment / turnover / sectors / funds / style。
**由 `--context` 显式声明**（机器不宜替你判断）：`mainline_matrix`、`prev_pool`、`events`、`verification_points`、`health_thresholds`。缺省即不注入，按 `unknown` 处理。组装后自动调用技能生成器做一次契约校验，通过才落盘。

### 关键坑：宽度/指数/板块是「最新快照」接口，**不能回填历史交易日**

- `clist`（全A行情、板块资金流）与 `ulist.np`（指数行情）**没有 `date` 参数**，永远返回"当前最新"快照。
- 只有涨停池/跌停池/炸板池（`push2ex`, `date=`）、日K线（`push2his`, `klt=101`）、两融（`datacenter-web`）能按日期取历史。
- 后果：若把别日的宽度/指数挂到今天的标签下，会**静默混日期**——这是本技能明令禁止的。
- 工具用 `f124`（行情更新时间戳）反推快照所属交易日，与 `--date` 不符时**默认直接拒绝**，需显式 `--allow-date-mismatch` 才继续（相关章节自动标 `partial` 并在 `status_reason` 写明观察到的日期）。
- 实测：9/14 盘后跑工具抓到的快照 `f124` = 9/15 盘中 → 守卫正确拦截。

### 验证：按日期精确取值的部分逐值复现

用 9/14 的 K 线缓存 + `--allow-date-mismatch` 复跑，**date 精确**的字段与当日手工结果完全一致：
涨停 55 / 跌停 16 / 炸板 30 / 封板尝试 85 / 最高板 4；成交额、前值、5日、20日均值四项分毫不差。
宽度/指数/板块因是快照接口，工具如实标 `partial` 并注明快照日期。

### 其他

- `push2his` 密集请求会整体限流（含编号备用主机），此时用 `--kline-cache` 复用已落盘 K 线；工具把抓取成功的 K 线自动缓存，失败即回退。
- 板块引用用**板块代码**（`f12`，如 `BK0438`）而非名称；`--context` 的 `themes[].boards` 必须是代码，且必须落在 `sectors.items[].id` 里，否则工具在组装时就报错。
- `--sector-top`（默认 15）控制行业资金两端各收录多少个，避免 496 个板块把报告撑爆。


## 十二、个股颗粒度四项结构（2026-09-15）

### 背景：与第三方 PDF 复盘的覆盖对照

对照对象是《A股全景复盘｜2026-09-14（周一）》。结论：**主干（指数→宽度→情绪→主线→资金→延续性→验证点）本技能全覆盖**，对方多出来的是一层「个股颗粒度」。按该 PDF 的章节逐条对齐：

| PDF 章节 | 状态 | 落地位置 |
|---|---|---|
| 指数/宽度/涨跌停/情绪指标/跨源口径注 | 已覆盖 | `indices` / `breadth` / `short_term_sentiment` + `universe` |
| 情绪周期定位（高潮→冰点→修复） | 已覆盖 | 五态 `ice/euphoria/divergence/repair/neutral` + 连续历史 |
| 双确认主线矩阵＋象限读法 | 已覆盖 | `mainline_matrix`（含可选失血线） |
| 行业主力资金流 Top 进出 | 已覆盖 | `sectors` + `fund_flow` |
| 概念层资金流（含风格项） | **本次补齐** | `sectors.concept_view`（第二套分类） |
| 板块→个股下钻 | **本次补齐** | `sectors.items[].leaders` |
| 最高板质量检查 | **本次补齐** | `short_term_sentiment.high_boards` |
| 连板梯队分布 | **本次补齐** | `short_term_sentiment.streak_distribution` |
| 游资下一步推测 / 方向性结论 | **有意不做** | 技能红线：不预测次日方向、不给买卖或仓位指令 |

### 坑一：追加结构**不能新增顶层章节**

`normalized_sections` 会把 `SECTION_NAMES` 里每个缺失章节补齐为 `unknown`，`coverage()` 又对全部章节计数。所以只要往 `SECTION_NAMES` 里加一项，**所有历史输入**的「可得N / 部分N / 未知N」就会变，向后兼容立刻破裂。

正确做法：把新结构挂到既有章节之下（`short_term_sentiment.*` / `sectors.*`）。顶层章节只允许在**版本升级**时新增。四项落地后 `SECTION_NAMES` 未变，`make test` 里有一条回归用例守着「未声明即逐字节一致」。

### 坑二：整列 unknown 不该占版面

`high_boards` / `leaders` / `concept_view` 的字段大多是可选的。若按固定列渲染，9/14 这种「只有资金流、没给涨跌幅」的数据会渲染出一整列 `unknown`，既不美观也容易被误读成「这里本该有数」。规则是**只保留至少一行有值的列**：整列无证据就不出现。这与「不用 0 补缺」是同一条纪律——没有证据就留白，而不是留空壳。

### 坑三：梯队必须与涨停家数同池自洽

PDF 的 4板1/3板3/2板7/首板44 **合计正好 55 = 当日涨停家数**，这正是可校验的不变量，已写进契约：

- 各档家数之和必须等于 `breadth.limit_up`（必须包含首板，否则会被当成另一套口径而拒收）；
- 最高档必须等于 `metrics.highest_streak`。

两条都对不上就拒绝。**注意**：东财涨停池不含 ST、指数级涨跌家数含 ST，两者不是同一股票池；如果梯队来自涨停池而 `limit_up` 来自另一口径，这里会直接暴露，不要靠文字说明绕过。

### 坑四：概念层必须真的独立成表

东财行业（`m:90 t:2`）与概念/风格（`MSCI中国`、`融资融券`、`科技风格`、`CPO概念`）是两套不同体系。混排会把「融资融券」「大盘股」读成行业，得出错误结论。契约要求 `concept_view.classification` **必须区别于** `sectors.classification`，同体系直接拒收；渲染上净流入/净流出也是**分别排序**、不与行业榜合并。

### 坑五：个股颗粒度是归因，不是推荐

四项结构都会出现个股名。这是**板块与情绪的结构归因**，不是选股输出。因此：

- 每张个股表都强制带「只列输入显式声明的个股……不构成个股推荐」的声明；
- `fund_flow` 必须配 `fund_flow_method_category`（多为 `provider_model`），报告按该类别披露，不得写成交易所事实；
- `high_boards` 只统计「净流入为正/为负的只数」（零点是方向分界，不是调参阈值），**不作评级、不给排序建议**；
- 输出仍要过 `forbidden_terms` 禁词门（买入/加仓/目标价/止损等一律拒发）。

### 真实数据验证（9/14）

`research/daily-review-0914-backfill/market_extended.json` 用 PDF 原值装配（未做任何估算），产出 `report_extended.{md,html,json}`：

- 连板梯队 4板1/3板3/2板7/首板44，合计 55，首板占比 80.00%；
- 最高板质量 4 只：净流入为正 3、为负 1（闽东电力 +0.55亿/换手12.3%、超声电子 +2.82亿/19.3%、中新赛克 +0.13亿/1.06%、凯盛新能 -0.01亿/10.4%）；
- 概念层 12 项净流入 / 14 项净流出，与行业层分开成表；
- 板块内个股 4 个板块（元件/医药生物/通信设备/磨具磨料），元件链「核心缩量、二线高换手」的分层一眼可见。

**向后兼容复核**：用同一 `--history-dir` 口径重跑未声明四项的 `market_C.json`，`report_C.md` / `report_C.html` **逐字节一致**；`summary_C.json` 除 `run.history_path`（我们主动换的临时目录路径）外全字段相同。


## 十三、三个东财接口的历史回溯边界（2026-09-15 实测）

评估「股性/个股行为画像」这类跨期统计时才发现：本技能所用的东财接口，**保留窗口差了三数量级**。逐日打 `date=` 参数、看 `tc` 是否大于 0 得到的边界：

| 接口 | 用途 | 实测可回溯 | 证据 |
|---|---|---|---|
| `push2his` 日K（`klt=101`） | 涨跌幅 / 成交额 / 量价 | **几乎全历史** | 600519 返回 6005 根，最早 2001-08-27 |
| `datacenter-web` 龙虎榜明细 `RPT_DAILYBILLBOARD_DETAILSNEW` | 龙虎榜命中 | **≥ 1 年** | 2025-09-15 仍有 71 条；2026-09-11 为 68 条 |
| `push2ex` 涨停池 / 跌停池 / 炸板池 | 涨停家数、连板、炸板率 | **仅约 3–4 周** | 2026-08-26 `tc=52` 可得，2026-08-24 `tc=0` 不可得 |

后果与纪律：

- 单日复盘不受影响（只用当日）。但**任何跨月、跨季的「历史档案」都不能指望 `push2ex`**——它只留最近约 3–4 周。要长期回溯只有两条路：① 每日跑一次取数工具逐日累积；② 用日K的**涨跌幅字段（`f57`）**自算涨停（日K没有窗口限制）。
- 自算涨停**不要用「今收 − 昨收」**：前复权序列在除权日会失真。用接口直接给的涨跌幅字段，并**按板块区分涨跌幅限制**（主板 10% / 创业板·科创板 20% / ST 5% / 北交所 30%），否则 20% 板的票会被系统性漏判。
- 龙虎榜接口**自带 `D1/D2/D5/D10/D20/D30_CLOSE_ADJCHRATE`**（上榜后第 1/2/5/10/20/30 个交易日的复权涨跌幅）。做「拉完次日给不给肉」「追高回撤多深」这类统计时直接用这几个字段，不必自己拼K线；但它们是**事后字段**，任何时点判断都只能用观察窗已满的样本，否则是前视偏差。

  `sections.short_term_sentiment.high_boards` / `sections.sectors.items[].leaders` 的逐值比对，可复算。

1. `security_details.cross_check_tolerance_pct` 成为**新输入的必填项**。校验器用

4. r010 是 1.4 输入，走升级豁免路径，**重放结果与历史交付逐值一致**（只有版本号、
   `legacy_migration` 说明和新增的 `concentration_scope="complete"` 默认值不同）。回归用例
   `test_legacy_1_4_input_is_exempt_from_1_5_disciplines` 守护这条豁免。

顺带一条：构建脚本里「下一修订号 + supersedes」应该**从历史目录自动推导**，不要写死常量，
否则每改一次都得手改脚本，容易跳号或指错 SHA。

## 十八、断档日回填与 deep 输入的四个新坑（2026-09-17）

本节来自 9/17 复盘当日实测（9/16 未跑过、历史缺档）。

### 坑一：中间断档一天，上一期验证点会被「错日期结算」

`resolve_verification_points` 的窗口是 `上一历史日 < event_date ≤ 当日`。9/16 缺档时直接跑 9/17，
9/15 声明的 9 个 `event_date=2026-09-16` 点会全部落进窗口，并用 **9/17 的观察值**结算
（`observed_market_date=2026-09-17`）——点问的是 9/16，答案取的是 9/17，静默混日期。

**正确做法**：先为断档日组装一份 `post_close` 回填注册输入（revision=1，as_of=当天），
生成一次把它注册进历史，再跑当日。回填输入能结算的部分：成交额（K线）、量比/均线（benchmark）、
高标连板（池）、主题涨停家数（mainline+两个板块K线涨跌幅）。不能结算的部分如实 unknown：
宽度/上涨占比/涨停净差（快照不可回填）、炸板率（derive 要求情绪+宽度双 available）、
晋级率（**prev_pool 硬依赖 breadth 非 unknown**，fail-closed）。实测 9/15 的 9 点 = 5 passed / 4 unknown。

### 坑二：历史 r 文件里的 deep 组件是「归一化后形态」，不是输入形态

生成器在派生时把 `liquidity_regime.benchmarks[]` 的各指标解包成纯数值再落历史。
照抄 r 文件会以为 benchmark 字段是 plain float——**输入必须是证据对象**（value/unit/observed_at/source），
否则 `必须是object` 拒收。同理 `capital_co_movement` 必须带 `thresholds`（至少
`pseudo_sector_top1_share_pct`）与 `methodology`；`lhb_structure` 标 unknown 时**不能**携带
methodology 等任何分析数据（「unknown不得携带分析数据」是硬门，status_reason 单独保留）。

### 坑三：个股多窗口可以全部走当日快照，不再需要第二口径

`ulist.np` 快照一次返回 f62/f267/f164/f174（1/3/5/10日），当日盘后跑复盘时四个窗口同源同口径，
`cross_check_tolerance_pct` 可以压到 0.5。坑十六的「1日列分裂成两套供应商」只在隔日回填时才会发生。
板块资金首位个股（京东方/药明康德/沐曦这类非涨停票）不在涨停池快照里，要单独补一次 ulist 批量。

### 坑四：断档日的宽度类验证点结算 unknown 是「结构性」的

涨停净差/上涨占比/炸板率/晋级率四类点的观察值全部依赖当日 breadth（或与 breadth 同池的派生），
而 breadth 是快照接口、无日期参数。**任何断档日这四类点都只能 unknown**，不是采集不力；
回填输入的 status_reason 里应保留池交集等备查证据（如「9/15池32只∩9/16池=12只」）供人工追溯。

### 坑五（2026-09-17 r002 实测）：构建脚本手写「计划时刻」当 fetched_at/cutoff_at，会整体未来计时

r001 交付复核发现：`build_ctx.py` 与 `build_deep_0917.py` 给 ctx 注入证据统一盖了
`17:05`、deep 注入盖了 `17:25`、cutoff_at 写 `17:40`——而实际抓取在 15:25–15:59、
组装 16:03 完成，**358 个 fetched_at 全部晚于真实采集时刻**。数值本身真实（来自当日落盘
快照），但时间戳口径失实：close 快照声称覆盖到 17:40，实际只到 16:03；契约校验拦不住
（cutoff ≥ 所有 fetched_at 内部自洽即可通过），只能靠「当前时刻 vs 文件 mtime vs 输入内
时间戳」三方对照发现。

- **纪律**：构建脚本里 `fetched_at`/`cutoff_at` 一律取真实墙钟（`datetime.now(timezone)`
  或复用取数批次已落盘的真实时刻），禁止手写「预计盘后某某点」的计划时刻。
- **修正路径**：纯元数据修正也要走 r002 修订链（文本级替换三组时间戳字符串 → revision+1 →
  `supersedes_sha256` 指向 r001 信封的 `input_sha256`），实测 r002 与 r001 报告仅快照头
  三行不同，数据与分析逐字节一致。
- **复核口径**：`grep -o '2026-09-17T1[7-9]:' | sort | uniq -c` 类快速扫描输入内时间戳
  分布，与 `date` 和文件 mtime 三方对齐后再注册。

## 十九、条件表的公开可读性（2026-09-17 r002 交付后用户反馈）

用户对深度层「量能、价格位置与历史分位」的原始条件表提出三点批评：英文码看不懂、
24 行重复且看不出属于哪个基准、只判成立/未成立没有解读。落地改法（schema 标签 +
deep_render 矩阵化）：

- **机器码必须有公开中文标签**：新增 `schema.LIQUIDITY_CHECK_LABELS`（8 个条件码），
  渲染层 `_check_label` 取用，未识别码保留原文不静默丢弃。关系符用 `≥/≤` 而非 `` `>=` ``。
- **逐行重复表改成矩阵**：行=基准、列=条件（列头含阈值）、单元格=观察值+✓/✗，
  6 行替掉 24 行；市场级条件单独小表。同一道理适用于其他「同一组条件 × 多主体」的展示。
- **逐条解读必须由数值确定性生成**：`_liquidity_reading` 只从当日已派生数值归纳
  （收涨/收跌、量比分档措辞、均线位置、120日分位半区），分档阈值写死在代码里可复算，
  不引入主观措辞，结尾声明「不预测方向」——这条红线不能为了「更有分析感」而破。
- **展示精度对齐**：条件单元格的百分比统一两位小数（`_observed`），与同节指标表一致；

- 回归提示：这是渲染层升级，历史 deep 输入重放的该章节输出会随新版变化，属预期；

## 二十、资金共现「整列 unknown」的三个连环坑（2026-09-17 r003 实测）

用户对 r002 报告「Top1占比/HHI/反向个股/伪板块四列全 unknown」的反馈，追出来三个层面的坑。

### 坑一：板块成分接口单页上限 100 只，按 f62 降序取一页会系统性丢掉负值尾部

`fetch_today_extra.py` 抓 `b:{board}+f:!2` 成分时 `pages=1` 写死：汽车零部件实际 281 只，
只拿到 f62 降序前 100 只（全部净流入），**负值尾部 180 只全丢**——Σ前100=+36.46亿 vs 板块
+30.40亿，缺的 -6.06亿 正是流出股。元件 67 只、面板 42 只未超页限所以恰好完整。
**纪律：成分抓取必须翻页取全（rows<100 才 break），抓完用 Σf62 对账板块口径。**

### 坑二：板块级聚合值 ≠ 成分股逐只加总，差百元级「聚合噪声」

三组全成分 Σ 与板块 f62 的相对偏差：元件 2.9e-8、汽车零部件 7.2e-9、面板 1.0e-7
（面板绝对差 234 元）。旧校验 `abs_tol=1.0 元` 会把真实全成分数据拒收。已改为
`math.isclose(sum, total, rel_tol=1e-6, abs_tol=1.0)`：放行噪声、仍能拦下缺一只
正常体量成分股（偏差通常 ≥ 百万分之一）。契约文档已同步。

### 坑三：「样本就先交差」是错的默认值；渲染层不许印整列 unknown

r002 的组装脚本只带进了每组 5 只「资金前列个股」，标 `contributions_complete=false`
就交付——但全成分数据一次翻页抓取就能拿到，**降级应该是穷尽手段后的结果，不是省事的
默认**。两层修复：

- **契约层**（deep-analysis.md）：`complete` 是默认目标；`sample` 只用于全成分客观不可得
  的场景。停牌无报价个股不计入并写明数量（本次安达股份 1 只）。
- **渲染层**（deep_render.py）：贡献不完整时集中度四列整列隐藏，改为一行降级说明
  （含各组已覆盖只数）——与第十二节「整列 unknown 不占版面」同一纪律，此前漏掉了
  capital 组件。

### 补充（2026-09-17 第三次可读性反馈）：四轴主题表的「单字列名+裸三态」同样没人看得懂

## 二十一、公开报告读者语言门禁：英文字段码零容忍（2026-09-17 第四次可读性反馈）

用户规则：复盘报告是给普通用户看的，**任何英文字段码/枚举/ID 都不允许出现**。此前各渲染
模块把内部码原样漏给读者（inventory 实测单份报告 44 种：unknown×34、sector_leader×16、
divergence×12、provider_model、inflow/outflow、dual_confirmed、CNY/count/percent、
`turnover_amount >= 1700000000000 CNY` 这类条件表达式、pcb-outflow 组ID、verify-xxx 点ID、
all-a-non-st 股票池ID、`hypothesis`/`correlation_only` 标记、A-SHARE 品牌眉线……）。

三层治理（已全部落地，192 项测试通过）：

1. **集中标签层**（`schema.py`）：情绪五态/快照类型/分析模式/方法类别/个股身份/资金角色/
   伪板块状态/验证范围/量价结果/章节名/全部验证指标（25个封闭集）+象限短名/运算符符号，
   统一中文映射；`formatting.py` 新增 `humanize_condition_value`（CNY→亿元、count→家、
   ratio→倍）与 `translate_rule_text`（蛇形码/状态码/布尔/and-or-not/算子逐词替换，不改语义）。
2. **源头中文化**：derive/four_axis/analysis 的规则串与证据文案直接写中文
   （"涨停家数高于前值 且 …"、"板块资金净流入 > 10.00亿元 且 涨停家数 ≥ 2"），
   比渲染端翻译更稳；legacy 兼容警告同样去码。
3. **硬门禁**（`public_language.py`，生成器出口调用）：Markdown 全文 + HTML 剥离
   style/script/标签/实体后扫描三类泄漏——蛇形码、短横线ID、枚举词表（含自由英文短语
   兜底词），命中即 `ReviewError` 拒绝写盘并列出词与次数。**门禁让"输入声明的公开文本
   自带码"也无处可藏**：r003 的 public_caveat 写了"（provider_model）"、funds 的
   public_status_reason 写了"保持unknown"，都被拦下，出 r004 清理后放行。

坑与注意：

- HTML 扫描必须先删 `<style>/<script>` 块再剥标签，否则 CSS 类名（badge-available、
  state-ice）会全部误报。
- 输入侧声明的 public_* 文本是渲染层忠实转述的，**写输入时就不能夹码**；门禁是最后防线，
  不是第一道。
- 测试断言大量随中文化更新（旧英文断言如 `A-SHARE / DAILY INTELLIGENCE`、`stock:华正新材`、
  `dual_confirmed` 象限值、`UNKNOWN` 空态、`DEEP · 深度交付` 全部改中文）。内部错误信息与
  摘要 JSON 不受门禁约束（审计层），只拦公开 md/html。
- "Top1"（第一大国流占比）作为惯用金融术语保留大写，不进禁词表。

### 补充（2026-09-17 第五次反馈）：六轴矩阵是审计面，不是阅读面——先结论后明细

中文化之后用户仍批评「听不懂、没价值信息」。根因不在语言而在**信息架构**：
- 7 个主题 6 行同判（横向未确认），一行信息摊成 6 列 × 7 行的噪音墙；
- 6 列里 2 列（时间轴/量价）是全市场同一判定逐行复读，图例自己都承认；
- "支持/冲突/未知"是合规词汇，回答不了读者真正的问题（今天谁强、强在哪、差什么）。

重构（four_axis_render + four_axis 派生行补字段）：

1. **速览在前**：`当日主线速览`表——主线｜当日判定（象限中文）｜关键数据（涨停N家｜板块资金±X亿）
   ｜催化与验证｜读法。按象限序（双确认→资金先行→情绪→失血）+涨停家数排序，天然形成强弱序。
   读法由结果码+象限+资金符号确定性生成，且**分支到资金符号**：bleeding 且资金为正 →
   「均未达确认线（资金为小幅净流入）」，为负 →「资金净流出」——不能按象限一律说净流出（9/17
   风电 +2.61 亿落在失血象限，说净流出就是错话）。
2. **大盘环境只说一次**：时间轴/量价合并为一行上下文（"大盘环境（各主题共用）：时间轴反向、
   量价反向"），不再进主题表。
3. **明细降级**：六轴逐项矩阵移入折叠块（md 用 `<details>`，HTML 用 method-details），
   保留规则复算与图例——审计价值不丢，只是不再占阅读主位。
4. 派生行补 `limit_up_count / board_fund_flow_cny / catalyst_count / verification_count /
   has_own_verification`，速览全从既有数据取，无新增口径。

**可复用原则**：合规矩阵（N 个主体 × M 项检查）不能直接当主展面——先给按结论分层的速览
（每行信息互不相同），再把矩阵折叠成审计附件；同一判定绝不逐行复读。

### 补充（2026-09-18 排版事故）：品牌层注入顺序与选择器特异性

1. **症状**：读者版 HTML 整页排版塌陷——标题与段落间距全无（挤成一堵墙）、表头变成
   10px 等宽字距体、1080px 图表右缘被裁。用户一句"排版有很大问题"定位到的根因不在
   读者版模板，而在共享层契约：`ashare_shared` v2 把品牌层 `<style id="ashare-brand">`
   **注入在 `</head>` 前、即技能样式之后**（有意为之，让品牌层覆盖技能遗留组件样式）。
   读者版首版 CSS 全是裸元素选择器（`h2{}`、`p{}`、`th{}`），被品牌层的基础复位
   `h1,h2,h3,p{margin:0}` 与 `table/th/td` 复位整体压掉；图表 1080px 超出 980px 正文栏，
   又遇品牌层 `body{overflow-x:hidden}`，右缘直接裁掉。
2. **修复**：读者版全部选择器锚在 `main` 下（`main h2`、`main th`、`main img{max-width:100%}`），
   以特异性 0-0-2 胜过品牌层 0-0-1，注入顺序不再影响排版。列对齐交给 markdown 表格
   行内 style（`---:` 列 python-markdown 会输出 `style="text-align:right"`，行内样式最高），
   不再写 `td:nth-child(n+2)` 全表右对齐——那会把"上榜原因"这类长文本列也右对齐。
3. **回归测试**：`PageCssScopingTests` 断言页面样式含 `main h2{`/`main img{max-width:100%`、
   不含任何行首裸元素选择器、品牌层注入在页面样式之后。改 CSS 时测试会守住这条线。
4. **教训**：跨层拼 HTML（技能模板 × 共享品牌层）时，任何"我以为我说了算"的裸元素选择器
   都是定时炸弹；约定注入顺序后，下游模板必须用更高特异性（作用域前缀）自保，不能靠
   书写顺序。

## 二十四、9/20 回放 9/17 的通道经验（2026-09-20）

### 坑一：push2ex 涨停池需要 ut 令牌，且存在「单次不完整池」毛刺

- 不带 `ut` 的 getTopicZTPool 对历史日期返回空 data（9/17、9/18 同样为空），**必须带
  `ut=7eea3edcaed734bea9cbfc24409ed989` + `pagesize=1000`**。
- 同一参数下出现过一次交集=6、重抓三次后恢复交集=9 的毛刺——**单次返回可能不完整**。
  历史池回溯后必须做四项对账（当日家数/最高板/前池规模/晋级交集），不等则重抓，
  连续多次一致才可用；本技能的 `_check_pools` 断言正是这道守卫，不要绕过。

### 坑二：push2his 周末整机限流，K线类补充走同花顺插件批量
