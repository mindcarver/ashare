# 每日复盘实测口径与避坑清单

本文件收纳运行 `ashare-daily-market-review` 时踩过的真实口径问题。**每次跑之前至少扫一遍第一节「最高频三条」。**

来源标注了沉淀日期，供判断是否已被上游修复。新增经验请按主题追加到对应小节，不要写回 SKILL.md 正文——SKILL.md 是操作手册，这里才是经验库。

---

## 一、最高频三条（每次必看）

1. **采集通道故障 ≠ 数据缺失**（2026-09-10）。走代理时 `push2.eastmoney.com` 会高频返回 `ProxyError / RemoteDisconnected`，此时先换备用主机并串行长重试，**不要直接判 unknown**。
2. **不同来源的涨停家数不能互认**（2026-08-29、2026-09-10）。东财涨停池不含 ST，财联社盘后统计口径也不同；即使方向一致也不能当作同一股票池。
3. **滚动均值窗口必须显式声明**（2026-09-10）。取 20 日均值时数据长度不足会被静默算成更短窗口，数值偏小且不易察觉。

---

## 二、股票池口径

### 涨停家数供应商差（2026-08-29、2026-09-10）

- 腾讯自选股 `data_changedist`（全样本含 ST）与财联社盘后统计（不含 ST/退市）存在差异。
- 实测 2026-09-10：东财涨停池 `tc=35`，财联社盘后统计 39~40。
- **即使差异不改变某次阈值结果，也不能把两个股票池声明为完全一致。** `short_term_sentiment` 最多标 `partial` 并输出 unknown，或改采同一股票池的完整数据。
- 报告须写清采用哪一套，并保持宽度与情绪同源。

### 东财涨停/炸板/跌停池不含 ST（2026-09-10）

- 实测当日池内 0 只 ST，而 ST龙元 +10.19%、*ST宝馨 +10.05% 均未入池。
- 但指数级涨跌家数 `f104/f105/f106`（上证指数/深证成指/北证50）**含 ST 与风险警示股**。
- 两者不能声明为同一股票池。

### 重建同池宽度的可行做法（2026-09-10）

用 `push2delay` 的 `clist/get` 分页枚举全 A：

```
pz=100，约 56 页，每页 ≈0.5s
```

再按名称剔除含 `ST` / `*ST` 的个股，即得到与涨停池一致的非 ST 股票池。

- ⚠️ `fs` 里的 `f:!2` 实测**并未**剔除 ST，必须另行按名称过滤。
- 实测 2026-09-10 全样本枚举得 955 涨 / 4512 跌 / 84 平，与财联社收评完全一致，可作交叉校验锚点。

### 封板尝试次数反推（2026-08-29）

财联社披露炸板数与封板率时：

```
limit_attempts = 涨停数 + 炸板数   （必须同一来源同一口径）
```

勿用「最终涨停家数」替代分母。

### 炸板率分母（2026-09-10）

```
炸板率 = 炸板池tc / (涨停池tc + 炸板池tc)
```

2026-09-10 为 22/57 = 38.60%，与新闻口径 37% 有差（分母不同），**不强行对齐**。

## 三、采集通道与重试

### 备用主机矩阵（2026-09-10）

| 主机 | 用途 | 实测可用性 |
|---|---|---|
| `push2.eastmoney.com` | 通用 | 走代理时高频 `ProxyError` / `RemoteDisconnected` |
| `push2delay.eastmoney.com` | `clist` / `ulist` | 多数时间可用 |
| `push2his.eastmoney.com` | K 线 | 多数时间可用 |
| `push2ex.eastmoney.com` | 涨停池 | 本次全程可用 |
| `datacenter-web.eastmoney.com` | 两融 | 本次全程可用 |

遇到连接类报错的处理顺序：**换备用主机 → 串行长重试（≥8 次、指数退避）→ 仍失败才降级**。降级时必须在 `status_reason` 写明是采集通道故障而非上游无数据。

## 四、成交量与滚动指标

### 5 日 / 20 日均值口径（2026-08-29、2026-09-10）

- 用上证指数 + 深证成指指数 K 线 `amount` 加总近似（**不含北交所**），口径写入 `status_reason`。
- ⚠️ `lmt=15` 会把 20 日均值静默算成 15 日均值。取 5/20 日均值时 **`lmt` 至少 25**，并显式写 `window.trading_days`。
- 不要用短期窗口的数值充当更长窗口的均值——数值偏小且不易察觉。

### 沪深成交额近似口径（2026-09-10）

上证指数 + 深证成指日 K 线 `amount` 加总（不含北交所），实测与新闻披露的「沪深两市成交额」一致（2026-09-10 为 16,471.48 亿元），可直接使用。

### 前一交易日成交额核验（2026-08-29）

`data_quote` 的历史日期参数可取前一交易日收盘，用于 `previous_amount` 核验。

## 五、资金数据

### 两融滞后（2026-08-29）

`data_market_overview type=margin` 的 row 常为空（仅 schema）。当日复盘若两融未发布，标 `partial`，或改用证券时报数据宝 WebSearch。

### 北向数据已断供（2026-09-10）

`push2his .../kamt.kline/get` 返回逐日相同常量（0.00 或固定值），**不可当作净流入使用**。funds 章节只保留交易所两融事实，其余标 `partial` 并说明原因。

### method_category 门禁（2026-08-29）

- 仅有供应商模型或活跃度代理时，funds 不能标 `available`。
- 北向成交额不是方向性净流入，不能作为资金方向证据。

---

## 六、事件文本与禁词

### 事件描述也过禁词检查（2026-08-29）

质量门的 FORBIDDEN 检查覆盖事件描述。写事件时避开价格/指令类词：

- 「机构上调目标价」→ 改为「机构上调其股价预期」
- 资金流向统一用「净流入/净流出」，**不要用「净买入/净卖出」**（会触发禁词误报）

## 七、脚本维护

### 已修复的缺陷（2026-09-10）

- `verification_points` 的 Markdown 列表原先被误嵌在 `qualitative_verification_points` 分支内，导致新 schema 下只输出「后续验证点：」标题而无条目。
- `repair` 未评估时的措辞误指为「缺少前一交易日指标」，实为更高优先级状态先行命中。

两处均已修好。改脚本后务必跑测试——**从仓库根跑 `make test`，或在本技能目录跑**：

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

### 禁词与设计令牌已上移共享层

本技能的禁词表与设计令牌不再定义在生成脚本内，而是由 `skills/_shared/` 提供：

- 禁词 tier：`no_price`（不允许任何价格锚点）
- 令牌 + 页面外壳：渲染末尾由 `ashare_shared.inject_shared_css()` 注入
- 真源：`skills/_shared/forbidden-terms.json`、`_shared/design-tokens.css`、`_shared/shell.css`

**不要在脚本里重新内联禁词表、`:root` 色值或页面骨架规则**——`make audit` 与 `make test` 会直接报错。

### 脚本结构（已按审计 P2-5 拆分）

原先 1,761 行的 `generate_daily_review.py` 已拆为同目录多个模块，**CLI 调用方式完全不变**：

| 文件 | 职责 |
|---|---|
| `generate_daily_review.py` | CLI 入口：参数解析、编排、写盘（唯一入口） |
| `schema.py` | 错误类型、Schema 常量、日期/文本断言、`value()` |
| `validate.py` | 输入读取、Schema 1.0 归一化、全部契约校验 |
| `derive.py` | 判读派生、历史序列、验证点 |
| `render.py` | Markdown 与 HTML 渲染 |
| `_paths.py` | 把 `skills/_shared` 挂到 `sys.path` 的唯一入口 |

改动时不要只看入口脚本：漂移可能藏在任一模块里，`make audit` 会扫描 `scripts/` 下所有 `.py`。
