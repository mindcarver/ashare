# 读者版证据契约

## 单一计算入口

`render_reader_report.py` 先调用 `load_input` / `validate_input`，再调用基础与深度派生。公开报告、图表、交互页不另造主线阈值、情绪分数、证券分类或截止时间。历史 `market.json` 原样保留；新校验结果写独立侧车。

`--date` 必须等于 `market_date`；公开信息截止取 `snapshot.cutoff_at`，不能把盘后修订写成收盘时已知。`--history-dir` 只结算已经到期的同对象、同口径验证。

## 可选补充输入

`reader_extra.json` 可包含 `stock_inflow`、`stock_outflow`、`volume_scan`、`zt_pool`、`previous_zt_pool`、`stock_windows`、`breadth_rows`、`etf_klines`、`index_klines`、`lhb_rows`、`board_history`。每个非空补充块需在 `evidence.<块名>` 中保存：

- `observed_at`：目标交易日；前池用 `previous_market_date`。
- `published_at`：真实发布日期，不晚于报告 `as_of`。无法确认实际发布日期时，仅可用抓取日作为保守可见边界，并同时声明 `publication_basis: known_by_fetch`；该值不代表真实发布日期，不能回填为交易日。
- `fetched_at`：真实抓取时刻，不晚于报告 `snapshot.cutoff_at`。
- `source`：复用主契约的来源对象（id/name/url 或合法 derived 引用）。只存内部。
- `method_category`：公开披露事实、模型推导、派生或活跃度代理的内部枚举。
- `volume_scan` 另需 `window: {trading_days: 5, end_at: market_date}`。

元数据必须来自实际取数记录，不能为使旧数据通过而回填虚假日期。行内 `f124`、日K `date`、龙虎榜 `TRADE_DATE` 与元数据同时存在时必须一致。日序列裁剪到目标日，缺目标日返回未知。

证券用精确代码去重、关联。补充涨跌与主输入相差超过0.03个百分点，或同口径资金偏差超过0.5%（金额绝对容差下限1元）时，整块拒用，待回查源数据；不要按经验选一边。该容差只处理舍入，不能许可不同供应商混用。缺失不是0，平盘不是“涨跌缺失”。

`board_history.boards` 沿用每板块 `name` 与 `rows: ["YYYY-MM-DD,净额"]`；净额变化只在两个日期均有值时计算。未来记录不参与报告。板块按ID与主输入关联，当日净额交叉核验，不允许用名称相似或另一快照替代。重复日期、非有限金额、主输入不存在的板块均拒用。历史新取证应产生盘后修订，不伪装成当日收盘证据。

`zt_pool` 自带 `amount/fund` 时优先使用同池同日数据；不应再用无日期成交额快照交叉拼接封单质量。相邻两池的交集、总数、最高板与主输入不一致时拒收。

## 宽度与图文一致性

宽度原始记录必须证明同一交易日；逐代码去重，按声明股票池过滤ST、停牌等，再与主输入上涨/下跌/平盘逐项对账。文件名不是日期证据。旧缓存逐行时间戳可供校验，但发现含ST与非ST声明冲突时，应暂停该宽度统计及其派生判断。

七桶固定为：`x ≤ -9`、`-9 < x ≤ -5`、`-5 < x < 0`、`x = 0`、`0 < x < 5`、`5 ≤ x < 9`、`x ≥ 9`。平盘不使用浮动阈值。正文与图表都使用 `breadth_distribution` 的同一结果；缺逐股分布时只画已校验汇总的涨/跌/平三桶，不伪造尾部数据。

封板率与炸板率使用主输入同池的 `limit_attempts`；同池涨停与炸板能够组成分母时须满足两率互补。不得借用其他池的家数。

## 分析边界与深度验收

- 净额变化不是当天流出；某板块净额增加可能只是净流出缩小。图表分别标“净额减少/净额增加”。
- 主线成员和阈值来自主输入。行业和概念单独成表；不使用“名称互含”建立身份关系，父子板块不可当独立样本相加。当前多板块主题不发布未经证明可相加的合计及双确认；应在主输入提供经过核实的单一聚合板块ID，或继续标明需去重。也可声明 `representative_board_id` 作为明确的资金参照（须属于 `boards`），但必须披露与主题成员的范围差异，不冒充主题整体净额。
- 逐证券保留行业，不把跨行业热股挂在第一只的行业下。换手、跌幅、资金比值是描述性对照，不能证明先后波次或机构身份。
- 多周期资金、量价条件、情绪历史、共现与集中度、催化、龙虎榜六组件都要呈现。`unknown` 有明确说明；主输入已可得内容不能因读者版省略。
- 情绪短窗口注明实际起止日与样本数，不声称20/60日分位。条件未满足不等于市场趋势被证伪。
- 事件输出事实/发布日期、假设、传导、反证和验证对象；原始新闻转述不作为已核实事件。
- 主力资金推导与龙虎榜披露范围不同，方向相反只说明需对照口径，不能自动判断“资金异常”。

人工 `insights` 只接受 `causal_status: hypothesis`、`text`、精确代码 `anchors`、非空 `counter_evidence` 和 `verification`。锚仅验证对象与对照数据，不认证自由文本里的额外数字或机制；需人工逐项核对，公开语言出口仍执行检查。旧无锚洞见、自由新闻及产业映射旁路不自动发布。

## 验证

运行全仓测试与编译；测试必须调用实际入口、渲染函数或共用派生，不能复制实现后自测。至少验证错日、未来记录、未知与零、边界桶、资金环比、跨行业、条件变动、空输入以及深度六组件。真实回放保留历史原件，核对 MD/HTML/图表/交互页；内部校验JSON保存所有排除原因。通过“能生成文件”不等于证明行情或新闻真实性。

## 增量采集入口

`tools/fetch_reader_extra.py --date YYYY-MM-DD --output <新文件>` 只采集当日可确认的个股榜和按日期披露的龙虎榜，生成 evidence 元数据；历史最新快照错日时保留缺口。`tools/fetch_board_backfill.py --input market.json --output <新文件>` 生成带元数据的 board_history 补充块，裁掉未来记录；合并补充包时同时保留 evidence 键。ETF、量比及其他块由可证明日期和窗口的通道按本契约提供，不能以最新值回填。两工具不会覆盖已存在的文件，也不会在导入模块时发请求。补抓时间晚于报告截止须创建新的盘后修订，再生成报告。

## 完整分析与复核

执行[读者版深度与历史修订](reader-depth.md)：量价日线重算、原始快照与历史交叉匹配、昨日池分组、主题参照及正文结构均受该规则约束。
